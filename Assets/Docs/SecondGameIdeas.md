## 플랫폼 판단

막혔던 곳은 **알리는 것**, 목표는 **빨리 수입**.

| 보기 | 판단 |
|---|---|
| 스팀 (작게, 5~6달러 이하) | **1순위.** Unity·Steam 출시 경험 재사용. 3~4개월 범위. |
| 로블록스 (무료 + 인게임 결제) | 차선. 플랫폼이 노출해 주지만 새로 배워야 하고 개발자 몫이 작음. |
| 모바일 디펜스 (심혈) | 보류. 가장 많은 노력을 광고비가 승부를 가르는 시장에 넣게 됨. |
| 모바일 퍼즐/퀴즈 (간단, 광고 수익) | 부업 실험 정도. 정기 수입으로 기대하지 않음. |

- 스팀과 로블록스는 **묶어서 기획 불가** — 돈 버는 구조(한 번 구매 vs 매일 복귀+결제)가 달라 기획 뼈대가 다르다. 플랫폼을 먼저 정하고 기획한다.
- 스팀으로 가면 **만들기 전에 상점 페이지부터** 열어 찜 반응을 본다. 찜 없이 출시하면 같은 문제가 반복된다.

## 스팀으로 간다면: 솔로 게임

- 이유: 1번째 게임에서 가장 어려웠던 것이 **테스트**(4인 협동은 원할 때 테스트 불가). 솔로는 혼자 바로 확인 가능.
- 대가: 친구를 끌고 오는 확산이 없음 → 움짤 한 장으로 궁금하게 만드는 장면이 필요.

## 핵심 아이디어: "나무에서 숲 보기" 연결 퍼즐

**확대·축소를 반복하며 여러 규모의 맵을 오가면서 서로 연결하는 게임.**

- 규모 예시: 회로 → 집 → 동네 → 발전소. 그 사이에 여러 단계의 확대/축소 세계가 있음.
- 소재: **전기**(현재 선호). 공식(V=IR)은 쓰지 않고 물건으로 — 스위치·콘센트·전등 등을 연결.
  - 전기를 고르는 이유: 설명 없이도 결과를 앎(이으면 켜짐, 잘못 이으면 터짐). 규모가 커지는 순서도 자연스러움.
  - 대안: 실 같은 단순한 것으로 연결 — 이 경우 "이으면 무슨 일이 생기는지"를 게임이 새로 가르쳐야 함.
- 잘못 연결하면 **펑 터지면서 기회가 날아감**.

### 이 게임이 되느냐를 가르는 것

한 규모에서 한 연결이 **다른 규모에서 눈에 보이는 결과**로 나타나야 한다.

- 되는 경우: 회로에서 선을 이음 → 집 전등이 켜짐 → 동네 지도에 불이 들어옴 → 동네가 과부하면 발전소가 터짐. 원인이 다른 규모에 있어 오가야만 풀림.
- 안 되는 경우: 규모마다 따로 푸는 퍼즐이고 확대·축소는 스테이지 고르는 연출일 뿐.

참고 선례(세계 안의 세계 퍼즐): Patrick's Parabox, Cocoon.

### 조심할 점

- 분량: 규모 하나마다 그림·규칙이 따로 필요 → 처음엔 **3단계**(회로·집·동네)만.
- 여러 규모에 걸친 퍼즐 설계가 코드보다 어려움. 제작 시간 대부분이 여기 들어감.
- 공부처럼 느껴지면 안 됨 — 몰라도 감으로 풀리고, 알면 더 잘 풀리는 정도.

### 미정

- 핵심 재미가 **주어진 문제 풀기**(스테이지 제작량 많음)인지 **자유롭게 짓다가 터뜨리기**(시스템 한 번 만들면 분량이 나옴)인지.
- 가격, 제목, 그림 방향, 에셋 활용 범위.
