**상태(2026-10-02):** 설계 진행 중. **코드·씬 미착수.** 타이틀의 Survival 버튼은 글자만 있음("Free Update Coming", 클릭 불가).

서바이벌 모드 SSOT. 스토리 모드 규칙은 기존 문서가 그대로 SSOT이고, 이 문서는 서바이벌에서 달라지는 것만 적는다.

[`CoopStageAudit.md`](CoopStageAudit.md)(스토리 협동 규칙), [`CheerSystemDesign.md`](CheerSystemDesign.md)(응원).

**범례:** [확정] = 사용자 승인. [제안] = 에이전트 제안, 승인 전. [미정] = 사용자 답 대기.

## 2. 확정 스펙 [확정]

| 항목 | 규칙 |
|---|---|
| 형식 | **개인전.** 팀 생존 아님 |
| 인원 | **2~4인.** 1인 불가. 8인은 하지 않음(색 4개·스폰 4곳·UI 4칸·접속 상한 4) |
| 판 | 기존 미니게임(Grid 등)을 개인전 규칙으로 올린다 |
| 순서 | **랜덤.** 스토리처럼 M1→M5→Boss 순이 아님 |
| 점수 | 판마다 **순위로 점수.** 판 규칙이 달라도(버티기/도착) 순위는 공통이라 간단 |
| 사망 | 사망 처리 + 점수 처리 + **관전** |
| 기록 | **저장 안 함.** 같이 플레이 중인 사람들의 점수만 보여 준다. Steam 리더보드 없음 |
| 적 | 공격 가능한 적 없음. 체이서는 나올 수 있음 |
| 진입 | Tutorial을 거치지 않고 **전용 대기 씬** |
| 판 씬 | 스토리 씬을 재사용하지 않고 **서바이벌 전용 씬**을 따로 만든다 |
| 매치 종료 후 | **대기 씬으로 돌아가 한 판 더** |
| 개인 버프 | **그대로 둔다.** Space로 각자 사용(투표 없음, `CheerService.RequestSelfBuffServerRpc`) |

## 3. 미정 [미정]

### 3.1 매치 종료 방식

사용자 답: "최종 1인이 나올 때까지 진행". 어느 뜻인지 확인 필요.

| 안 | 내용 | 4인 기준 | 걸리는 점 |
|---|---|---|---|
| A. 판 안에서 1인 | 각 판은 1명 남을 때까지, 탈락 순서로 순위 점수. 매치는 판 수 또는 목표 점수에서 끝 | 판 수 자유 | 매치 종료 조건을 따로 정해야 함 |
| B. 매치 전체 탈락제 | 판마다 꼴찌가 매치에서 탈락, 마지막 1인 우승 | 3판이면 끝 | 순위 점수가 필요 없어짐. 첫 탈락자는 끝까지 구경 |

에이전트 이해·추천: **A + 목표 점수 선착**(예: 먼저 10점). "순위로 점수"라는 확정 스펙과 맞고 마지막까지 역전 가능.
경주형 판은 "1명 남을 때까지"가 아니라 "전원 도착 또는 시간 종료"로 끝나야 한다 — 판 종류별 종료 조건을 따로 적을 것.

### 3.2 팀 외침

문제: 지금은 함정이 경고를 띄우면 전원이 팀 단어를 외쳐 **되돌린다**(`CheerService` + `ITeamCheerRevert` —
입 닫힘·침·혀·조임·안개). 개인전에서는 되돌리면 모두가 이득이라 외칠 이유가 없다.

| 안 | 내용 | 평가 |
|---|---|---|
| 1. 탈락자의 외침 = 함정 호출 (에이전트 추천) | 관전 중인 탈락자가 팀 단어를 외치면 함정이 발동·가속 | 관전자에게 할 일, 판이 늘어지는 것 방지 |
| 2. 먼저 외친 1명만 보호 | 경고 중 가장 먼저 외친 사람만 피함 | 개인 버프(보호막)와 겹침, 인식 속도 싸움 |
| 3. 서바이벌에서는 끔 | 함정은 자동 주기로만 | 가장 쌈, 음성 기능이 사라짐 |

1안 비용: 지금 코드는 "경고 중 외침 → 되돌림" 한 방향뿐. 함정 5종 각각에 "지금 발동" 진입점이 새로 필요.
필요 인원 규칙(탈락자 전원? 1명?), 쿨다운, 함정 없는 판(Grid 등)에서 부를 대상을 정해야 한다.
2인 매치는 탈락자가 생기면 판이 끝나 이 기능이 안 나온다.
절충: 1차는 3안으로 내고 1안을 후속 업데이트로.

## 4. 뼈대 [제안]

| 항목 | 제안 | 근거 |
|---|---|---|
| 대기 씬 | `TutorialNetworkManager`(접속 즉시 스폰·색 자동 배정·모이기 발판·Steam 초대)를 새 씬에 그대로 배치. 바꿀 것은 "게이트 통과 후 목적지" 한 곳(지금은 M.Stage1 고정) | Steam 초대는 Host가 있는 씬으로 자동 동기화됨 |
| 모드 값 | 지금 모드를 담는 곳이 없다(`LobbyContext`는 Host/Client만). 서바이벌 여부를 담을 자리 필요 | — |
| 판 진행 | Host가 시드로 판 목록을 섞어 진행 | `SceneFlowManager`는 `sceneSequence`의 "다음 씬"만 감 — 서바이벌용 진행 경로 추가 필요 |
| 사망 | 그 판에서 탈락, 부활 없음 | `StageNetworkState`의 `Disable Revive` 체크박스가 이미 있음(T5 사용) |
| 판 종료 | 순위 확정 → 점수판 → 다음 판 | 지금은 "실패 = 같은 씬 리로드"(`BeginStageResetOnServer`)뿐. **새 출구 필요 — 가장 큰 코드 작업** |
| 점수 | 순위 점수(예: 4·3·2·1), 동률은 같은 점수 | 버티기형 = 탈락 순서, 경주형 = 도착 순서 |
| 점수 보관 | Host가 매치 동안만. 씬이 바뀌어도 남는 자리(DDOL) | 저장 안 함(§2) |
| 관전 | 탈락하면 카메라가 생존자를 따라감, 키로 대상 전환. 자유 시점 없음 | `ThirdPersonCamera` 대상만 교체하는 최소 형태 |
| 방해 | 펀치(넉백, 데미지 0)는 그대로 | 이미 있는 PvP 동작 |
| 이탈 | 누가 나가면 방 종료(현행) | 재접속·중간 참가 없음 규칙 유지 |

### 4.1 그대로 지키는 제약

- 오프라인 없음. 이동 = Owner, HP·데미지·규칙 = Host, 데미지는 `NetworkDamageUtil`만.
- 씬 로드는 Host만. 랜덤은 Host 시드 배포 후 각자 재생성(`StageNetworkState` 챌린지 슬롯, 씬당 동시 1개).
- 타이틀 문구는 번역 안 함. 인게임 문구는 13개 언어.

### 4.2 새 씬 이름 규칙 (코드가 이름으로 판정)

- 플레이어 배치 스폰: 씬 이름에 `Stage`/`Boss`/`Interlude`가 있어야 함(`PlayerSpawnManager.IsStageScene`).
- 전환 효과음: `M.`/`T.` 접두사(`SceneFlowManager.PlayStageTransitionSfx`).
- 스폰 좌표: 색별 고정 4곳(원점 ±5m) — 씬을 원점 기준으로 제작.
- 팀 목숨·실패·함정 동기화: 씬에 `StageNetworkState` 필요.

## 5. 판별 적합도 — **잠정** (개별 코드 미확인)

| 분류 | 판 | 개인전 전환 |
|---|---|---|
| 버티기형 | Grid 안전 칸, 바닥 붕괴(M5·M.Boss P4·T.Boss P3), 화살·낙하(M1), T5 체이서, T4 깨지는 타일, T3 위액 | 쉬움 — 탈락 순서가 순위 |
| 경주형 | 통로 달리기(T1·T3), T.Boss P1 붕괴 트랙 | 중간 — 협동 문·패드를 빼야 함 |
| 팀 조건형 | SideSplit, SequenceRing, ColorTile 점수제 | 어려움 — 규칙을 새로 짜거나 제외 |

사용자가 Sequence를 예로 들었다 — SequenceRing은 지금 "팀이 함께 순서 맞추기"라 개인전 규칙을 따로 정해야 한다.

## 7. 조사에서 확인한 사실 (2026-10-02)

- 서바이벌용 코드는 없다. `Survival` 이름은 `TimerUI.TimerMode.Survival`·`SurviveTimeObjective`(스토리 버티기 타이머)뿐 — 무관.
- `Enemy*.cs`는 없다(문서에만 Enemy 도메인). 움직이는 위협은 `Stage5ChaserAI`뿐.
- 저장은 옵션용 PlayerPrefs뿐(`GameSettingsManager` 등). 기록·통계 시스템 없음.
- Steam 로비는 Private 고정·초대 전용(`SteamLobbyManager`). 접속 상한 4.
- 팀 목숨 = 인원−1, 씬 단위(`StageNetworkState.TeamLivesRemaining`). 서바이벌에서는 부활을 끄면 소모되지 않는다.
- 사망 중에는 콜라이더 제거·`PlayerDead` 레이어·입력 차단(`Player.Die()`), Cheer 도메인은 `IsDead` 가드가 없어 죽어도 외칠 수 있다.
- `End` 씬은 플레이어를 스폰하지 않는 선례다(`SceneFlowManager.WaitsForPlayersOnEnter`) — 점수판 전용 씬을 둘 경우 참고.
