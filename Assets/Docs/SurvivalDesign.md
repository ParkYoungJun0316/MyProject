# Survival Design (서바이벌 모드)

**상태(2026-10-06):** 설계 진행 중 — 매치 규칙·판 목록·판별 규칙 9개·대기 씬·진입 확정. **다음 할 일은 §0.** **코드·씬 미착수.** 타이틀의 Survival 버튼은 글자만 있음("Free Update Coming", 클릭 불가).

서바이벌 모드 SSOT. 스토리 모드 규칙은 기존 문서가 그대로 SSOT이고, 이 문서는 서바이벌에서 달라지는 것만 적는다.
관련: [`NetworkDesign.md`](NetworkDesign.md)(권한·씬 로드 문·이탈), [`ReviveSystemDesign.md`](ReviveSystemDesign.md)(사망·부활),
[`CoopStageAudit.md`](CoopStageAudit.md)(스토리 협동 규칙), [`CheerSystemDesign.md`](CheerSystemDesign.md)(응원).

**범례:** [확정] = 사용자 승인. [제안] = 에이전트 제안, 승인 전. [미정] = 사용자 답 대기.

## 0. 다음 세션 시작점

**진행 방식:** 기획을 단위 하나씩 닫는다. **한 번에 한 단위만, 짧게** — "핵심 3가지 → 규칙안 → 정해 주실 것 3~4개".
코드를 읽어야 하면 먼저 조사하고, 답을 받으면 이 문서에 기록한다. 설명은 쉬운 말로.

**닫힌 것(10/5):** 매치 규칙(§5.1), 판 목록 9개(§5.2), 2판째 진행 방식(§5.2.0), 스토리 코드 보호 원칙(§4.3),
**판별 규칙 9개 전부**(§5.2.1~§5.2.9).
**닫힌 것(10/6):** 대기 씬·진입(§4.4), 판 종료 흐름(§4.5 — 점수판 두 단계 화면만 [제안]), 관전(§4.6),
화면·문구(§4.7), 펀치·이탈·버프(§4.8). **다음 단위는 6번 문서 잠금 해제·구현 순서.** 남은 [제안] 표시는 그때 한 번에 확인받는다.

**바로 다음 할 일 — 남은 단위 (이 순서 추천):**

| 순서 | 단위 | 정할 것 |
|---|---|---|
| 6 | 문서 잠금 해제(§6)·구현 순서 | **사용자 승인 후** 반영. 아직 어느 문서도 고치지 않았다 |

**2번 단위(판 종료 흐름)를 시작할 때 먼저 읽을 코드:** `Flow/SceneFlowManager.cs`(씬 로드·커튼·`sceneSequence`),

**해석 확인 완료(10/6):** §5.1 순위 시각(각자 PC가 시각을 찍어 보냄·0.05초), §5.2.8 외우기(색별로 차례로 짧게),

**열려 있는 작은 것 (맵 설계·플레이 때 정함):**

## 3. 닫힌 쟁점 (2026-10-05 확정, 아래 표는 검토 기록)

- **3.1 매치 종료 = A안.** 각 판은 1명 남을 때까지. **목표 점수 없음** — 고른 판을 전부 한 뒤 총점 1등이 우승.
- **3.2 팀 외침 = 3안(끔).** 1안(탈락자 함정 호출)은 후속 업데이트 후보.

### 3.1 매치 종료 방식

사용자 답: "최종 1인이 나올 때까지 진행". 어느 뜻인지 확인 필요.

| 안 | 내용 | 4인 기준 | 걸리는 점 |
|---|---|---|---|
| A. 판 안에서 1인 | 각 판은 1명 남을 때까지, 탈락 순서로 순위 점수. 매치는 판 수 또는 목표 점수에서 끝 | 판 수 자유 | 매치 종료 조건을 따로 정해야 함 |
| B. 매치 전체 탈락제 | 판마다 꼴찌가 매치에서 탈락, 마지막 1인 우승 | 3판이면 끝 | 순위 점수가 필요 없어짐. 첫 탈락자는 끝까지 구경 |

에이전트 이해·추천: **A + 목표 점수 선착**(예: 먼저 10점). "순위로 점수"라는 확정 스펙과 맞고 마지막까지 역전 가능.
경주형 판은 "1명 남을 때까지"가 아니라 "전원 도착 또는 시간 종료"로 끝나야 한다 — 판 종류별 종료 조건을 따로 적을 것.

### 3.2 팀 외침

문제: 지금은 함정이 경고를 띄우면 전원이 팀 단어를 외쳐 **되돌린다**(`CheerService` + `ITeamCheerRevert` —
입 닫힘·침·혀·조임·안개). 개인전에서는 되돌리면 모두가 이득이라 외칠 이유가 없다.

| 안 | 내용 | 평가 |
|---|---|---|
| 1. 탈락자의 외침 = 함정 호출 (에이전트 추천) | 관전 중인 탈락자가 팀 단어를 외치면 함정이 발동·가속 | 관전자에게 할 일, 판이 늘어지는 것 방지 |
| 2. 먼저 외친 1명만 보호 | 경고 중 가장 먼저 외친 사람만 피함 | 개인 버프(보호막)와 겹침, 인식 속도 싸움 |
| 3. 서바이벌에서는 끔 | 함정은 자동 주기로만 | 가장 쌈, 음성 기능이 사라짐 |

1안 비용: 지금 코드는 "경고 중 외침 → 되돌림" 한 방향뿐. 함정 5종 각각에 "지금 발동" 진입점이 새로 필요.
필요 인원 규칙(탈락자 전원? 1명?), 쿨다운, 함정 없는 판(Grid 등)에서 부를 대상을 정해야 한다.
2인 매치는 탈락자가 생기면 판이 끝나 이 기능이 안 나온다.
절충: 1차는 3안으로 내고 1안을 후속 업데이트로.

## 4. 뼈대 [제안]

| 항목 | 제안 | 근거 |
|---|---|---|
| 대기 씬 | `TutorialNetworkManager`(접속 즉시 스폰·색 자동 배정·모이기 발판·Steam 초대)를 새 씬에 그대로 배치. 바꿀 것은 "게이트 통과 후 목적지" 한 곳(지금은 M.Stage1 고정) | Steam 초대는 Host가 있는 씬으로 자동 동기화됨 |
| 모드 값 | 지금 모드를 담는 곳이 없다(`LobbyContext`는 Host/Client만). 서바이벌 여부를 담을 자리 필요 | — |
| 판 진행 | Host가 시드로 판 목록을 섞어 진행 | `SceneFlowManager`는 `sceneSequence`의 "다음 씬"만 감 — 서바이벌용 진행 경로 추가 필요 |
| 사망 | 그 판에서 탈락, 부활 없음 | `StageNetworkState`의 `Disable Revive` 체크박스가 이미 있음(T5 사용) |
| 판 종료 | 순위 확정 → 점수판 → 다음 판 | 지금은 "실패 = 같은 씬 리로드"(`BeginStageResetOnServer`)뿐. **새 출구 필요 — 가장 큰 코드 작업** |
| 점수 | 순위 점수(예: 4·3·2·1), 동률은 같은 점수 | 버티기형 = 탈락 순서, 경주형 = 도착 순서 |
| 점수 보관 | Host가 매치 동안만. 씬이 바뀌어도 남는 자리(DDOL) | 저장 안 함(§2) |
| 관전 | 탈락하면 카메라가 생존자를 따라감, 키로 대상 전환. 자유 시점 없음 | `ThirdPersonCamera` 대상만 교체하는 최소 형태 |
| 방해 | 펀치(넉백, 데미지 0)는 그대로 | 이미 있는 PvP 동작 |
| 이탈 | 누가 나가면 방 종료(현행) | 재접속·중간 참가 없음 규칙 유지 |

### 4.1 그대로 지키는 제약

- 오프라인 없음. 이동 = Owner, HP·데미지·규칙 = Host, 데미지는 `NetworkDamageUtil`만.
- 씬 로드는 Host만. 랜덤은 Host 시드 배포 후 각자 재생성(`StageNetworkState` 챌린지 슬롯, 씬당 동시 1개).
- 타이틀 문구는 번역 안 함. 인게임 문구는 13개 언어.

### 4.3 구현 원칙 — 스토리 코드 보호 [확정 10/5]

출시된 스토리 모드가 깨지면 안 된다. 기존 경로를 쓸지, 새로 짤지는 아래로 정한다.

- 기존 코드에 **가볍게 얹을 수 있고 버그 가능성이 거의 없으면** 기존 것 + 경로 추가.
- 경로 추가가 **무겁거나, 기존 안정 코드를 다시 꼼꼼히 테스트해야 할 정도면** 서바이벌 전용 스크립트를 새로 짠다.
  (새 코드만 테스트하는 것과 안정된 기존 코드를 다시 테스트하는 것은 무게가 다르다.)
- 적용 예: 2판째·runner 차례 전환의 씬 다시 부르기는 스토리의 실패 리로드 경로(`BeginStageResetOnServer`)를 고치지 않고
  서바이벌 전용 진행 스크립트가 맡는다 — §5.2.0·§5.2.9. 세부는 판 종료 흐름 단위에서 확정.

### 4.4 대기 씬·진입 [확정 10/6]

| 항목 | 규칙 |
|---|---|
| 타이틀 | Survival 버튼 = 바로 방 생성 → 대기 씬. 초대 수락은 지금과 같다(Host가 있는 씬으로 자동 동기화) |
| 스폰·색 | Tutorial과 같다 — 접속 즉시 스폰, 빈 색 자동 배정 |
| 시작 조건 | **전원이 모임 발판에 3초**, 단 **2명 이상일 때만.** 혼자면 "친구를 초대하세요" 안내 |
| 혼자 입장 | **허용.** 대기 씬에 혼자 들어가서 초대한다(Steam 초대는 방을 만든 뒤에만 가능) |
| 판 고르기 | 표지판 [E] 창에 판 9개 체크. **Host만 조작**, 기본 전부 켬, **1개만 골라도 된다.** 나머지는 보기만 [창 형태는 제안] |
| 매치 후 인원 변동 | 대기 씬에서는 **나간 자리에 새 사람 초대 허용** |
| 나가기 | Tutorial 게이트 전 규칙 — Client가 나가면 그 자리만 비고, Host가 나가면 방 종료 |
| 대기 씬에 둘 것 | 코스튬 표지판, 초대 버튼, 방 코드. 팀 구호 표지판은 뺀다(§3.2) [제안] |

구현 메모(조사 10/6):
- 대기 씬 관리는 **서바이벌 전용 스크립트를 새로** 짠다(§4.3) [제안]. `TutorialNetworkManager`는 접속 콜백에서만 캐릭터를 만들어
  (`OnClientJoined`), 매치 후 대기 씬으로 돌아오면 이미 접속해 있는 Client는 스폰되지 않는다. 게이트 인원 조건도 `connected > 0`이라 1명이 통과한다.
- Steam 빌드의 방 다시 만들기는 프로세스를 `+create_game`으로 재시작한다(`TitleMenuController.TryRestartForCreateGame`).
  이 인자에 모드가 없어 **서바이벌용 인자가 따로 필요**하다 — 없으면 Survival을 눌러도 Tutorial로 들어간다.
- Client는 모드 값을 받을 필요가 없다 — 씬을 따라오면 된다. 모드 값(`LobbyContext`에 자리 없음)은 Host의 진행 스크립트가 든다.
- 매치 중(판 씬)에 초대가 들어오는 것을 막는 방법은 미확인 — 판 종료 흐름 단위에서 확인.

### 4.5 판 종료 흐름 [일부 확정 10/6]

| 순서 | 일어나는 일 | 상태 |
|---|---|---|
| 1 | 판 종료 조건 충족 → 함정 전부 정지(`SceneFlowManager.FreezeAllHazardsNow` 재사용) | [제안] |
| 2 | 커튼 → **점수판 전용 씬** | [확정] |
| 3 | 점수판: 1~4등 줄에 **이번 판 점수가 더해지고, 순위가 바뀌면 줄이 자리를 바꾸는 것을 보여 준다** | [확정] |
| 4 | 점수판에 **다음 판 공개**(이름만 / 이미지만 / 둘 다 — 미정) | [확정, 표시 형태 미정] |
| 5 | **전원이 준비를 누르면** 다음 판으로. 2판짜리의 2판째는 같은 씬을 다시 부른다(§5.2.0) | [확정] |
| 6 | 마지막 판 뒤에도 점수판 씬에서 점수 계산 → **최종 점수·우승자** 표시 | [확정] |
| 7 | 전원 준비 → **대기 씬으로 복귀. 처음 들어왔을 때와 같은 상태**(전원 스폰, 발판에 모이면 다시 시작) | [확정] |

점수판 씬 세부 [확정 10/6]:
- **규칙 설명 = 점수판 씬의 "다음 판 카드"** — 스크린샷 1장 + 이름 + 규칙 한두 줄 + 순위 방식 한 줄. 판 안에서는 기존 Tab Tip이 보조.
  영상·gif는 1차에 만들지 않는다(반응을 보고 헷갈리는 판만 나중에 교체).
- **첫 판 앞에도 점수판 씬을 거친다** — 전원 0점 + 첫 판 카드.
- **UI만.** 캐릭터를 스폰하지 않는다(`End` 선례).
- 준비를 안 누르는 사람이 있어도 **30초 뒤 자동 진행.**
- 화면은 두 단계 [제안]: ① 점수 화면(점수 더하기·순위 바뀜, 자동으로 넘어감) → ② 다음 판 카드 화면(여기서 준비).
  점수와 규칙이 한 화면에 섞이지 않고, 규칙은 "그 판 바로 앞"에 나온다. 마지막 판 뒤에는 ② 자리에 최종 결과.

구현 메모(조사 10/6):
- `SceneFlowManager`는 "목록의 다음 씬"(`LoadNext`)과 "목록의 n번째"(`LoadSceneByIndex`)만 간다. 서바이벌 씬은 스토리 `sceneSequence`에
  섞지 않고 **이름으로 부르는 메서드 하나를 새로 얹는다** [제안] — 기존 경로는 바뀌지 않는다(§4.3).
- ESC Reset(`StageNetworkState.NotifyStageResetServerRpc`, 누구나 호출 가능)은 서바이벌에서 **숨긴다.**
  전원 동시 사망은 걱정 없다 — 씬의 Disable Revive를 켜면 `PlayerReviveState.OnDeathFromServer`가 실패·부활·목숨 소모 전에
  빠져나온다(확인 10/6). 판 종료 판정은 서바이벌 진행 스크립트만 낸다.
- 판마다 새 시드를 뽑아 배포한다(스토리 리로드의 `BroadcastNewSeedClientRpc`와 같은 방식).
- **매치 중 초대 차단이 없다** — 접속 승인은 인원 4 미만만 보고(`NetworkManagerSetup.ApproveConnection`), 로비는 생성 때
  `SetJoinable(true)` 그대로다. 매치 시작에 잠그고 대기 씬 복귀에 푼다. 스토리도 코드상 같은 상태로 보임(별건, 기록만).
- 점수판 씬에 플레이어를 스폰하지 않으면 `End` 선례를 따른다(`WaitsForPlayersOnEnter` — 지금은 `End` 이름 하나만 판정).

### 5.2.1 화살·낙하 버티기 (M.Boss P3) [확정 10/5]

- 규칙: 5×5 바닥에서 낙하물·화살을 피하며 버티기. 순위 = 죽은 순서.
- **데미지 1**(하트 5, 보호막은 한 발을 통째로 막음).
- **혀는 뺀다** — 팀 외침으로 되돌리는 방해 함정은 서바이벌에서 전부 뺀다(§3.2).
- 빨라짐은 **함정이 시간에 따라 추가되는 방식**이 기본. 예: 처음 DropTrap 2종 → 30초 뒤 2개 추가 → 30초 뒤 또 추가.
  기존의 "시작 후 N초 뒤 작동" 설정을 쓴다(사용자 표현 "active interval" — 정확한 필드 이름은 구현 때 확인.
  조사에서 본 것은 `DropTrap.fireAtSeconds`, `ArrowTrap.fireAtSeconds`, `TrapSpeedPhase.afterSeconds`).
  발사 간격 자체를 줄이는 표(에이전트 제안: 15초마다 −15%, 하한 낙하 2.5초·화살 3초)는 **보류 — 추가 시간표를 먼저 본 뒤 결정**.
- **끝 보장 = 바닥 부수기(가드).** 판이 길어지면 바닥 칸이 하나씩 꺼진다. 시작 시각·박자는 [미정](에이전트 제안: 90초부터).
- [미정] 함정 추가 시간표(무엇을 몇 초에 몇 개), 바닥 꺼짐 숫자.
- 조사(M.Boss P3 현재 값): `DropTrap_3` 5초마다 25칸 중 랜덤 1칸 / `DropTrap_8` 7초마다 생존자 각자 머리 위
  (`TrapPlayerTracker`, 죽은 사람 제외) / 경고 2초 / 화살 4개 각 7초, 경고 1.5초, 가까운 생존자 쪽으로 회전.
  탄속만 30~40초에 ×2(`TrapSpeedPhase`), **발사 간격은 고정**. 70초 타이머(`PhaseSurviveChallenge`)로 종료, 인원별 표 없음.
  P3 아래에 벽 없음(바깥 투명 벽 여부 미확인).

### 5.2.2 통로 달리기 (T.Stage3) [확정 10/5 — 맵 세부는 맵 설계 때]

- 순위 = 도착 순서, 못 온 사람은 0점(§5.1 경주형 순위). 죽으면 부활 없이 탈락.
- 구간 타이머는 현행 그대로: **첫 번째 사람이 구간에 들어오면 시작**, 시간이 다 되면 그 구간에 위액(1초마다 데미지 1)
  → 뒤처진 사람이 탈락. 코드 변경 없음(`SegmentTimer`, `SegmentAcidRise`, `ContactDamage`).
- 제한 시간: 지금 값(40/40/65…)으로 시작해 **빠듯하게 더 줄인다.**
- 문·발판: **넣는다. 1명이 밟으면 열림.** 1등이 문을 여는 부담을 지고 뒤가 따라붙는 **역전 장치**로 쓴다.
  방식(버티는 초, 위치)은 맵 설계 때 [미정]. 참고: `DoorPuzzleGroup.topology`를 Solo로 두면 필요 인원 1(인스펙터만),
  버티기 문은 `DoorController` duration 값, 문이 열리는 순간 막는 콜라이더가 꺼져 뒤 사람이 지나갈 수 있음(`JellyPopDoor`).
- 구간 수: **3~4구간으로 줄인다.** 맵 길이는 맵 설계 때 자세히 [미정](현재 전체 약 1,300m·5구간·달리기만 130초).
- 끝: **1등 도착 후 10초** 뒤 종료.
- 뺄 것: 식도 조임(팀 외침 함정). 가시·볼더·튕김 발판·벽 끼임은 유지.
- 새 코드: 도착 순서·시각 기록(지금 `ReachZoneObjective`는 누가 들어왔는지만 알고 순서·시각이 없음. 경주형 공통).

### 5.2.3 Grid 안전 칸 (M.Stage5) [확정 10/5]

- 규칙: 내 색 칸 또는 흑백 칸에 서기. 부서지는 바닥·바람·펀치 속에서 버티기. 판 5×5 그대로.
- 판정 실패 = **데미지 3**(즉사 아님). 낙사는 즉사(현행).
- 1명 남을 때까지 라운드 반복. 공개 시간 4.5초에서 라운드마다 −0.5초, 최소 2초(숫자는 플레이 조정).
- 탈락자의 색 칸은 **없앤다**(생존자 색 + 흑백만 뽑음).

### 5.2.4 Grid 변형 (T.Boss P3) [확정 10/5]

- 규칙: 색 없는 공용 칸, 한 칸당 1명. 겹치면 둘 다 실패. 판 모양을 바꿈(예: 6×10칸).
- 칸 수 = 생존자 수 + 라운드별 보정. 보정은 **+2에서 시작해 라운드마다 −1**, **최소 1칸**. 인원과 상관없이 같은 식
  (`max(1, 생존자 수 + 3 − 라운드)`). 아무도 안 죽을 때: 4인 6·5·4·3·2·1 / 3인 5·4·3·2·1 / 2인 4·3·2·1·1…
- 판정 실패 = **데미지 3**. 1명 남을 때까지.

### 5.2.5 색 타일 점수 (M.Stage3 `ColorTileChallenge`) [확정 10/5]

- 규칙: 타일 위에 2초 연속으로 서면 점수, 타일은 다른 자리로 이동. **내 색 타일 = 1점**(나만 가능), **흑백 타일 = 2점**(누구나).
- 흑백 타일은 **혼자 서 있을 때만 시간이 흐른다.** 다른 사람이 올라오면 멈춤 → 밀어내야 먹는다.
- 타일 수는 지금과 같다: 사람 수만큼의 색 타일 + **검정 1 + 흰색 1**.
- 사망 없음. **제한 시간 60초**, 끝났을 때 개인 점수 순으로 순위(같은 점수는 동률). 1판, 10·5·3·0.
- 입(암전) 함정은 뺀다. 화면에 개인 점수 4칸.
- 조사: 지금은 색 버킷별 팀 합계이고 **누가 점수를 냈는지 코드에 없다**(`ColorTile.HoldReady`는 예/아니오뿐,
  점수는 각 PC 로컬 필드). 판정은 Host만(`JudgeQuotaRoutine`). 개인 점수 기록·동기화, 흑백 1인 판정,
  "할당량 채우면 끝 → 시간 끝나면 순위"가 새 코드. 스폰 지점 33곳·`occupySeconds` 2초는 인스펙터 값.

### 5.2.6 정원 타일 경주 (T.Stage4) [확정 10/5]

- 판 성격: 앞벽·뒷벽(`MovingCorridor`)이 전원을 좁은 구간에 가둔 채 끌고 가는 **버티며 가는 경주.**
- 순위: 도착한 사람은 도착 순서 → 그 아래는 **늦게 죽은 사람이 높은 순위**(오래 살아남아 목적지에 가까이 간 사람).
  동시에 죽으면 동률이고 **높은 쪽 점수**(§5.1 공통 규칙 그대로).
- 벽: **간격은 좁게, 속도 변화는 크게.** 한 축 직선 이동 그대로라 인스펙터 값만 바꾼다(코드 없음).
- 타일: 지금과 같은 구성 — **정원 1명 타일**(2명이 서면 1.5초 뒤 영구 파괴, 줄면 취소) + **밟으면 파괴 타일**(1초)
  + **Lump**(`Breakable`, 닿으면 폭발·데미지 1·밀림).
- 길이: 310m → **200~250m, 약 1분.** 벽 속도를 올릴 것이라 플레이 타임을 보고 정한다.
- 죽음: 낙사, 부활 없음. 뺄 것: 안개(팀 외침 함정). 카메라: 각자 탑다운(통로 축만 따라감) 유지.
- 조사: 벽 속도는 시드로 뽑고 서버 시각 기준으로 전 PC가 같은 시뮬레이션(`MovingCorridor`). 씬 값 간격 24/30,
  뒷벽 {1.5,2,3,3.5}·앞벽 {-2,2,3,4}. 정원 판정은 Host(`BreakTileDirector`). 도착 순서·시각 기록은 없음(경주형 공통 새 코드).

### 5.2.7 밟으면 파괴 (T.Boss P1 `BreakTile`) [확정 10/5]

- 규칙: 넓은 판(사각 칸, **2층**)에서 계속 움직이기. 밟은 칸은 **1초 뒤** 영구 파괴(플레이 후 조정 가능). 떨어지면 탈락.
- 순위 = 떨어진 순서. 데미지 없음(낙사만). 칸이 복구되지 않아 가속 없이도 끝난다.
- 카운트다운 전에는 밟아도 파괴 예약이 걸리지 않게 한다. 펀치 그대로.
- 조사: `BreakTile`/`BreakTileDirector`에 트랙·협동 전용 로직 없음. 밟은 Owner가 신고 → Host가 첫 신고만 받아
  `ArmBreakTileClientRpc`. 칸은 NetworkObject 아님, 수 제한 없음(T.Boss 약 358칸). 여러 층 가능.
- 주의: 낙사 높이는 프리팹 고정(`fallAnimY` −5, `fallDeathY` −10, 월드 Y) → **모든 층은 y −5 위**. 스폰은 위층 위.
  위층 파괴 파티클(칸 아래 1m)이 아래층에 겹쳐 보일 수 있음.

### 5.2.8 기억 발판 (T.Stage2) [확정 10/5]

- 방식: **색별 길**(`ColoredMemoryPath` — 발판마다 안전한 색이 정해짐). 전원 같은 길은 기각(출발 직후 순위가 굳음),
  외우기 없는 보이는 길도 기각(T4와 겹침).
- 길 설계: **외우기 아주 쉽게**(단순한 길) + **겹치는 줄 2~3개** — 같은 줄을 누구는 좌→우, 누구는 우→좌로 지나가야 해서
  반드시 마주쳐 몸싸움이 난다. 밀려서 틀린 칸을 밟으면 죽는다.
- 틀린 발판 = **즉사**(현행 데미지 6, 하트 5).
- 외우기: 색을 **한 번에 같이 보여 주지 않는다**(겹치는 구간에서 색이 헷갈림). 지금처럼 색별로 차례로, 대신 길이 단순하니 **짧게.**
  초는 플레이 조정(현행 색당 3초 + 간격 1초).
- 시드: **손으로 만든 판 몇 장 중 시드로 선택 + 색 배정 섞기.** 자동 생성기는 만들지 않는다. 좌우 뒤집기는 좌표가 맞을지
  확신이 없어 **보류.** 2~3인일 때는 참가한 사람끼리 겹치는 짝에 색이 들어가게 섞는다 [제안].
- 2판. 순위 = 도착 순서. **1등 도착 후 10초 뒤 종료, 못 온 사람은 0점**(§5.1).
- 조사: 길은 씬에 손 배치 고정(발판마다 `safeColors` 인스펙터 값). 시드로 섞는 것은 Pioneer의 색-구역 배정뿐
  (`NetworkSessionData.Seed`, `GameSessionColorDistribution`). 틀린 발판은 데미지뿐이고 꺼지거나 떨어지지 않음.
  시작 연출은 전원 고정 탑다운 카메라(`MemoryPathIntroController`). 제한 시간 없음. 도착은 전원 필요(`ReachZoneObjective`).

### 5.2.9 문 미로 (T.Stage5) [확정 10/5 — 세부 일부 미정]

**형식 = 1 대 다.** (전원 runner 안은 기각 — 버티기 판이 이미 많고, 판이 넓어 서로 못 만나며, 새 코드가 더 많다.)

- 1층에 **runner 1명**, 나머지는 2층 **방해자**. 인원수만큼 차례를 돌아 전원이 runner를 한 번씩 한다.
- 순위 = **runner로 버틴 시간**이 긴 순. 표시 시간(소수 둘째 자리)까지 같을 때만 동률. 점수는 게임 1개로 보고 **10·5·3·0 한 번**.
- 문: 1층은 **흑/백 문 + common 고정문(항상 닫힌 벽)**만. 색 문은 쓰지 않는다.
- 방해자: 흑백 발판은 **방해자 누구나** 밟을 수 있다. 단 **자기 흑/백 상태를 발판 색과 맞춰야** 하고,
  한 색이 열리면 다른 색은 닫힌다(현행 `ColorGateController` 규칙 그대로). 목표는 runner를 빨리 죽게 만드는 것.
- 체이서: runner 한 명당 **60초 안팎**에 끝나도록 압박을 올린다. **B안 확정 — 추가 스폰 없이, 맞혀도 사라지지 않고
  속도만 오른다.** 5마리, 데미지 2(하트 5 → 3번 잡히면 탈락). 압박이 모자라면 그때 추가 스폰을 얹는다.
- 시작: **맵 중앙이 원점(0,0,0)**, 플레이어는 중앙(원점 ±5m)에서 스폰. **카운트다운 3초 뒤 바로 시작**(체이서 출발 포함)
  — 시작 방에 숨어 버티는 꼼수를 없앤다. Goal은 없다(새 맵).
- 차례 전환: 스토리의 "실패 → 리로드 + runner 재추첨" 경로를 고쳐 쓰지 않는다. **서바이벌 전용 스크립트**가 차례 순서를
  들고 씬을 다시 부른다(§4.3 원칙). 구체 방식은 판 종료 흐름 단위에서 `SceneFlowManager` 코드를 읽고 확정.
- 차례 사이 지도: 그대로 둘지, 시드로 섞을지 [미정](기억 발판에서 시드를 쓰므로 부담 없음).
- 조사(현재 T5): runner 추첨·돌아가며 맡기(`T5RunnerDirector`, `GameSession` 이력), 2층 발사대·발판, 체이서의 runner 추적,
  runner 전용 미니맵이 이미 있다. 문은 guide가 발판을 밟을 때만 바뀐다(타이머·예고 없음). 발판은 그 색 주인만 밟음
  (`ColorGatePad`). 체이서 5마리 고정·속도 4·맞히면 데미지 2 후 사라짐·한 번만 스폰(`Stage5ChaserSpawner` 가드)·가속 없음.
  누구든 죽으면 Fail → 씬 리로드 + runner 재추첨. Goal 칸은 체이서가 못 들어가게 파여 있음(숨는 자리 — 막아야 함).
  판 10×10칸·120m, 문 색 배치는 씬 고정(`t5doors.py` 시드 7036), 시드로는 4색 순열만 섞음(`SetDesignPermutation`).

### 5.2.0 2판짜리 진행 방식 [확정 10/5]

2판째는 **같은 씬을 다시 불러온다.** 체력·버프 쿨타임·부서진 칸이 한 번에 초기화된다.
다시 부르는 주체는 서바이벌 전용 진행 스크립트다(§4.3) — 스토리의 실패 리로드 경로를 고쳐 쓰지 않는다.

### 5.2.x Grid 공통 — 필요한 코드 (조사 10/5)

- `GridChallenge`는 `totalRounds`를 채우면 끝나는 구조 — **무한 반복 + 라운드별 가속은 새 코드**.
- `SharedSolo` 칸 수가 참가 색 수 기준(`GameSession.GetActiveColors`) → 생존자 수 기준으로.
- 판 크기는 코드에 고정돼 있지 않음(자식 `GridTile` 수집, 이웃은 간격으로 계산). `ExpectedTileCount = 25`는 경고만.
- 판 종료·순위 기록·팀 목숨/리로드 끄기는 공통 뼈대(§4).

## 7. 조사에서 확인한 사실 (2026-10-02)

- 서바이벌용 코드는 없다. `Survival` 이름은 `TimerUI.TimerMode.Survival`·`SurviveTimeObjective`(스토리 버티기 타이머)뿐 — 무관.
- `Enemy*.cs`는 없다(문서에만 Enemy 도메인). 움직이는 위협은 `Stage5ChaserAI`뿐.
- 저장은 옵션용 PlayerPrefs뿐(`GameSettingsManager` 등). 기록·통계 시스템 없음.
- Steam 로비는 Private 고정·초대 전용(`SteamLobbyManager`). 접속 상한 4.
- 팀 목숨 = 인원−1, 씬 단위(`StageNetworkState.TeamLivesRemaining`). 서바이벌에서는 부활을 끄면 소모되지 않는다.
- 사망 중에는 콜라이더 제거·`PlayerDead` 레이어·입력 차단(`Player.Die()`), Cheer 도메인은 `IsDead` 가드가 없어 죽어도 외칠 수 있다.
- `End` 씬은 플레이어를 스폰하지 않는 선례다(`SceneFlowManager.WaitsForPlayersOnEnter`) — 점수판 전용 씬을 둘 경우 참고.
