# Minigame Design

스테이지에 배치되는 **미니게임(챌린지)** 설계 SSOT. OX퀴즈 삭제 이후 신설 — 미니게임이 1개 더 추가될 수 있어, 특정 미니게임 하나에 종속되지 않는 별도 문서로 분리한다.

관련: [`NetworkDesign.md`](NetworkDesign.md) §11B (챌린지 축·`ChallengeOwnerType`·시드 동기화 SSOT), [`GameArchitectureBoundaries.md`](GameArchitectureBoundaries.md).

**범례**

| 태그 | 의미 |
|------|------|
| **[확정]** | 사용자 승인 완료 — 구현 시 그대로 따름 |
| **[설계 중]** | 방향은 잡혔으나 세부 미확정 |
| **[열린 질문]** | 구현 전 확인 필요 |

---

## 0. 배경

- **OX퀴즈 삭제 결정.** 플레이테스트 피드백: "공부하는 것도 아니고 머리 아프고 지루하다." → 삭제 후 다른 미니게임으로 교체.
- 영향받는 기존 자산: `OXQuizManager`/`OXQuizObjective`/`OXQuizTile`/`OXQuizUI` (사용 씬 `M.Stage2`, `T.Stage4`) — 제거 체크리스트는 §3 참고.
- `NetworkDesign.md` §9.1.4 매핑표("1 | `M.Stage2` | OXQuiz")도 이 미니게임 교체가 확정되면 갱신 필요 — 이 문서에서 먼저 설계를 잠그고 나중에 반영.

## 1. 미니게임 A — 좌우 분기 (가칭, 이름 미확정)

### 1.1 컨셉

통로가 **왼쪽/오른쪽**으로 갈라지고, 각 방향 끝에 도달 판정 지점이 있다. 라운드 시작 시 UI가 "몇 명이 어느 방향으로 가야 하는지"(+ 특정 색 포함 여부)를 공지하고, 플레이어들은 제한시간 안에 정확한 인원·색으로 재배치해야 통과한다.

예시:
- "왼쪽 3명, 오른쪽 1명"
- "왼쪽 1명(노란색), 오른쪽 3명"

### 1.2 확정 규칙 **[확정]**

| 항목 | 규칙 |
|---|---|
| 인원 분배 | **전체 인원이 반드시 다 나뉘어야 함** (좌+우 = 활성 플레이어 전원, 남는 인원 없음) |
| 인원 판정 | **정확히 일치**해야 통과 (지정 인원보다 많거나 적으면 실패) |
| 방향 | **좌/우 2분기만** (중앙·3분기 없음) |
| 색상 조건 | **라운드마다 선택적** — 색 없는 라운드도 존재. 초반 라운드는 색 조건 없이 시작, 전체 라운드 중 대략 3~5라운드는 색 조건 포함 (초반 완화 → 후반 난이도 상승 커브) |
| 판정 시점 | **타이머 종료 시점 스냅샷 판정** (OX퀴즈와 동일 — 실시간 유지 판정 아님) |
| 라운드 반복 | OX퀴즈처럼 **여러 라운드 반복** (동일 스테이지 인스턴스 내 N라운드 클리어해야 최종 클리어) |
| 페널티 | 오답(인원/색 불일치) 시 **데미지 적용 후 다음 라운드로 계속 진행** (OX퀴즈와 동일 — 재시도 루프 아님) |

> **주석 (해석 확인 필요):** 사용자가 말한 "총 5스테이지 중 대략 3~5스테이지는 색 조건"의 "스테이지"는 오버월드 스테이지(`M.Stage1`~`5`)가 아니라 **이 미니게임 인스턴스 내부 라운드 수**(OX퀴즈의 "1/5 문제"와 동일한 구조)로 해석했다. 다르면 §1.6에서 정정 필요.

### 1.3 라운드 구조 (해석, §1.2 주석 기준)

- 스테이지 인스턴스당 **5라운드** (OX퀴즈의 5문제 구조 계승 가정)
- 라운드별 랜덤 생성: ① 좌/우 인원 분배(전원 소진, 비균등 가능) ② 색 조건 유무 + 유무 시 어느 방향에 어떤 고유색 1개 필수
- 색 조건 등장 빈도: 초반 라운드는 색 없음 위주, 후반으로 갈수록 색 조건 등장 (전체 중 3~5라운드)

### 1.4 판정 · 페널티

- 타이머 종료 시점에 좌/우 각 판정 볼륨에 있는 플레이어 수·색을 스냅샷
- 판정 성공 조건: 좌측 인원 = 지정값 AND 우측 인원 = 지정값 AND (색 조건 있으면) 지정 색 플레이어가 지정 방향에 존재
- 실패 시: 전원 또는 오배치 플레이어에게 데미지(`NetworkDamageUtil`) → 다음 라운드 계속 (생존자 있는 한 진행, OX퀴즈 `JudgeByPosition` 패턴과 동일)

### 1.5 UI **[설계 중]**

- 기존에 없던 **문장형 동적 안내 텍스트** 필요: "왼쪽으로 3명" / "왼쪽 1명(노란색), 오른쪽 3명"
- 로컬라이즈 필요(다국어 String Table) — 숫자·색상명이 라운드마다 바뀌는 템플릿 문장 구조로 설계
- 진행도("n/m 라운드")는 기존 `ObjectiveUI`/`RoundProgressObjective` 패턴 재사용

### 1.6 열린 질문 **[열린 질문]**

- [ ] §1.2 주석의 "스테이지=라운드" 해석이 맞는지 확인
- [ ] 색 조건이 나올 때, 지정된 색의 플레이어가 애초에 게임에 없으면(비활성 색) 어떻게 처리할지 (활성 색 목록에서만 뽑아야 함 — `PlayerSpawnCoordinator.GetActiveColors()` 기준으로 필터링 필요, 설계상 자동으로 해결되긴 하나 명시 확인)
- [ ] 미니게임 A의 정식 이름
- [ ] 몇 개 스테이지(오버월드)에 배치할지 (OX퀴즈처럼 `M.Stage2` + `T.Stage4` 1곳씩만? 여러 곳?)

## 2. 구현 매핑 — 기존 챌린지 축 재사용

새 미니게임은 완전히 새로운 프레임워크가 아니라 **OX퀴즈와 동일한 §11B 챌린지 축**을 재사용하는 것으로 설계한다 (`NetworkDesign.md` §11B "OX에서 먼저 잠그고 복제" 원칙).

| 필요 기능 | 재사용 소스 | 비고 |
|---|---|---|
| 시드 동기화(Host→전체) | `StageNetworkState.ChallengeStart(seed, owner)` | 신규 `ChallengeOwnerType` 값 추가 필요 (§11B.9 owner 가드 패턴) |
| 라운드별 랜덤 생성 | `OXQuizManager.RegenerateQuestionOrder()` 패턴 (`System.Random(seed)`) | "좌/우 인원 분배 + 색 조건" 생성기로 교체 — `GameSessionColorDistribution`은 균등분배 목적이라 그대로는 못 씀, 신규 소형 유틸 필요 |
| 좌/우 판정 볼륨 | `OXQuizTile.GetPlayersInVolume()` (OverlapBox) | 2개 볼륨(좌/우)으로 복제, 판정 기준을 "정답 O/X"에서 "정확 인원수 + 필수색상 포함"으로 교체 |
| 라운드 진행도 목표 | `RoundProgressObjective` (`OXQuizObjective`와 동일 상속) | 그대로 복제 |
| 진행도 UI | `ObjectiveUI` | 그대로 재사용 |
| 시작 트리거 흐름 | `StageStartGate → StartStage/StartQuiz` 연동 | 그대로 재사용 |
| 오답 데미지 | `NetworkDamageUtil` | 그대로 재사용 |
| 문장형 안내 UI | (신규) | §1.5 참고 — 기존 프로젝트에 문장형 동적 텍스트 UI 없음, 새로 설계 |

**결론:** 코드 재사용률이 높아 난이도는 **낮음~중간**. 새로 설계할 부분은 "좌/우 인원+색상 랜덤 생성기", "좌/우 판정 볼륨 2개", "문장형 안내 UI" 3가지로 국한된다.
