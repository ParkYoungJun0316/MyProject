## 0. 한 줄 요약

1층 미로에서 **러너 1명**이 체이서를 피해 Goal까지 달리고, **나머지는 투명한 2층 바닥에서 내려다보며**
길을 안내하고 **색 패드를 밟아 문을 연다**. 맵 7장 중 **1장**을 시드로 뽑아 **한 판**만 한다.

## 1. 확정 결정

### 1.1 구조 — 한 판. 라운드는 없다 (2026-09-19 전면 교체)

> **T5는 T.Stage4와 같은 경로만 탄다.** 씬 로드 → 시드로 맵 1장 + 러너 1명 → 시작 → 클리어/실패.
> 스테이지 안에서 상태가 넘어가는 구간(라운드 전환)이 **없다.**

**저장소에서 허용하는 스테이지 형태는 둘뿐이다 (2026-09-19 사용자 확정):**

| 형태 | 예 |
|---|---|
| **(a) 씬 = 스테이지 1개** | T.Stage4, T.Stage5 |
| **(b) `PhaseManager` + phase마다 StageManager** | T.Boss 류 |

**"한 스크립트가 자체 상태기계로 라운드를 돌리는" 세 번째 형태는 만들지 않는다.**
구 T5(`T5RunnerRoundDirector` 552줄, `RoundPhase{Idle,Intro,Active,Done}`)가 정확히 그것이었고,
이것이 이번 교체의 이유다 — 기능이 모자라서가 아니라 **다른 스테이지와 형태가 달라서**다.

| 항목 | 결정 |
|---|---|
| 판 수 | **1** (맵 7장 중 시드로 1장) |
| 러너 | **1명.** 솔로 = 본인 |
| 러너 교대 | **없다.** 안 뛰어본 사람이 나오는 것을 감수(2026-09-19 사용자 확정) |
| 리로드 시 | 새 시드로 **맵·러너 재추첨**. 러너는 **로테이션**(§1.9) |
| 제한 시간 | **90초** (2026-09-19: 120→90. 실패 1회 비용을 줄여 러너 교대를 자주 돌린다) |
| 실패 | **러너 사망** 또는 시간 초과 |
| 클리어 | **러너가 1층 Goal + 안내자 전원이 2층 Goal** (§1.6) |
| 부활 | **러너는 부활 없음 — 사망 = 즉시 실패**(§1.6). SSOT는 `ReviveSystemDesign.md` §7.1 |

### 1.2 시작 시나리오 (2026-09-19 확정)

**텔레포트를 쓰지 않는다.** 플레이어는 스폰한 자리에서 물리적으로 2층에 올라간다.

| # | 시점 | 일어나는 일 | 주체 |
|---|---|---|---|
| 0 | 씬 로드 | 색별 고정 스폰 `(0,0,5)/(5,0,0)/(0,0,-5)/(-5,0,0)`. 커튼 덮인 채 | `PlayerSpawnManager` |
| 1 | `OnPlayersReady` | 시드로 **맵 1장 + 러너 1명** 확정 → 맵 활성화 → **러너 발판만 끄기** → 게이트 `t5.map` 해제 → 커튼 걷힘 | 디렉터 |
| 2 | 즉시 | 각자 자기 `ColoredStartZone` 안 → **3초 카운트다운** | `StageStartGate` |
| 3 | 카운트다운 완료 | `StartStage()` + **발판 활성화**(러너 것 제외) → 안내자가 투명 통로를 타고 2층으로 발사 | `OnCountdownComplete` |
| 4 | **2층 트리거 발동** | **발판 끄기 + barrier 전부 해제** (같은 스위치) | 디렉터 |
| 5 | 러너가 시작 존 이탈 | **체이서 4마리 스폰** | 이탈 트리거 |
| 6 | — | 러너 1층 Goal + 안내자 2층 Goal → 클리어 / 90초 → 실패 | T5 Objective |

**왜 이 순서인가 — 세 가지가 이 순서에 걸려 있다:**

1. **맵 활성화가 `OnPlayersReady`인 이유.** 사망 리로드 때 새 시드가 Host→ClientRpc로 오는데
   `Start()`보다 먼저 도착한다는 보장이 없다. T4가 판 선택을 미루는 그 이유와 같다.
   커튼이 덮고 있으므로 플레이어에게는 **"눈 떠보니 이 미로"** 로 보인다.
2. **barrier를 4단계까지 유지하는 이유.** 카운트다운 직후에 내리면 러너가 **옆 칸 발판을 밟아**
   2층으로 올라갈 수 있다. `ContactKnockback`에는 대상을 고르는 기능이 없어서, 발판이 켜져 있는
   동안 barrier로 막는 것이 유일한 구조적 차단이다.
3. **2층 트리거를 3단계에 미리 켜두지 않는 이유.** `ContactKnockback`은 **속도 방향을 보지 않는다.**
   미리 켜면 발사돼 올라가던 사람이 통과하며 **한 번 더 가속**돼 난간(6m)을 넘는다.

> **러너가 시작 존에서 안 나가면 체이서가 안 나온다 — 그대로 둔다.**
> 90초 타임아웃이 실패로 끝내므로 교착이 아니다. 없는 상황을 위해 코드를 늘리지 않는다
> (T4 §1.4와 같은 판단).

**수직 발사 수치:** `ContactKnockback.VerticalUp`. Player mass = 1이라 force가 곧 초기 속도이고
**정점 높이 ≈ force² / 19.62** — 2층 y≈25면 **force ≈ 22.1**이 정점에서 속도 0인 값이다.
모자라면 시작 홀에 도로 떨어지고 **발판을 다시 밟아 재발사**되므로(`knockbackInterval` 0.25초)
실패가 자기 복구된다. 넘치면 난간을 넘는다 — 실측으로 잡을 것.

### 1.3 2층에서 1층으로 못 내려간다

2층 바닥에 **발사 구멍이 하나** 필요하다(스폰 4자리가 ±5 안이므로 12×12 정도면 넷을 다 덮는다).
그 구멍은 곧 내려가는 길이기도 하다.

| 안 | 내용 | 상태 |
|---|---|---|
| **가** | 구멍에 **트리거 + `VerticalUp` 약하게** — 내려가려 하면 다시 올라감 | **채택(테스트 선행).** `ContactKnockback`은 `Is Trigger = true`를 명시적으로 지원하므로 **코드 0** |
| 나 | 전원 2층 도달 후 뚜껑 콜라이더 켜기 | 가가 실패하면 |
| 다 | 그냥 열어둠 | ✗ 안내자가 1층 미로로 걸어나가 2층 Goal에 못 감 |

> **가는 V단계에서 먼저 확인할 것**(2026-09-19 사용자 지시 — "테스트해보고 안 되면 방법을 강구").

### 1.4 문 / 패드 (배타적 색 게이트) — 유지

| 항목 | 결정 |
|---|---|
| 규칙 | 패드 1개를 밟으면 **그 색 문만 Open, 나머지 전부 Close**. 흑·백도 같은 규칙의 한 색 |
| **점유 = 마지막으로 밟은 패드** | **서 있는 것으로는 점유를 되찾지 못한다.** 발동은 `OnTriggerEnter` 하나뿐 — 재발동·되찾기 로직을 넣지 않는다 |
| 시작 상태 | 스테이지 시작 시 **전부 닫힘** |
| 맵당 문 | **15개** = 고유색 4색×2 = 8 + 흑 4 + 백 3 |
| 패드 | 2층에 색당 1개 = **6개**, 2층 곳곳에 흩어 배치 |
| 패드 권한 | 고유색 패드 = 그 색 플레이어만 / 흑·백 = 누구나 |
| 색 매핑 | **`SessionColorSlotMap`이 SSOT.** 이번 판에 없는 색 **+ 러너의 색** → `Common`. 러너는 1층이라 2층 패드를 밟을 수 없다. 2층 Common 패드는 **1개만** |
| 솔로 | 문 **전부 Open 고정**, 2층 패드 숨김 (2026-09-19 유지 확정) |
| 문 방식 | SlideUp, 닫힘 넉백은 기존 `DoorController` 그대로 |

러너 색 제외는 **라운드 단위가 아니라 스테이지 1회 적용**으로 바뀐다(호출 시점만 변경, 규칙은 동일).

### 1.5 체이서 (2026-09-19 전면 단순화)

| 항목 | 결정 | 구안 |
|---|---|---|
| 수 | **4마리 고정** (인원 무관, 솔로도 4) | 2~4인 8 / 솔로 6 |
| 스폰 위치 | **동서남북 4점 고정.** 맵과 무관하게 **씬 루트**에 둔다 | 맵마다 16점 |
| 스폰 시점 | **러너가 시작 존을 벗어날 때** | 라운드 시작 3초 뒤 |
| 데미지 | **2** | 1 |
| 피격 후 | 소멸(Host Despawn) — 변경 없음 | 동일 |
| 리스폰 | **없다** | 6초 뒤, 러너 30m 밖 |
| 타겟 | 러너만. 러너가 죽거나 은신이면 정지 | 동일 |
| 속도 | 8 m/s (러너 10) | 동일 |
| 문 | 닫힌 문은 체이서도 막음(`NavMeshObstacle` carve) | 동일 |

**스폰 4점을 맵에서 뺄 수 있는 이유:** 맵 7장이 원점에 겹쳐 있고 start/goal이 통일되므로,
**칸 중앙**에 두면 7장 전부에서 통행 가능한 자리가 된다(12×12 미로는 스패닝 트리라 모든 칸이 연결,
벽은 칸 경계에 선다). 랜덤화 축에서 빠져도 되는 이유는 **같은 4점이라도 매번 다른 미로**이기 때문이다.

> **⚠️ 체이서가 소모품이 된다.** 리스폰이 없고 때리면 소멸하므로 **4마리 = 러너를 때릴 기회 4번**이다.
> 러너 `maxHeart`가 5이고 데미지가 2라 **3방에 죽는다**(5→3→1→0) — 즉 2방까지 버틴다.
> 4마리가 다 소진되면 남은 시간은 무위험 구간이 되고, 압박은 90초만 남는다.
> **이것이 의도된 곡선이다**(2026-09-19 사용자 확정).

### 1.6 목표 / 실패 — T5 전용 Objective 하나

> **`SurviveTimeObjective`를 쓰면 안 된다.** 그건 **시간을 채우면 `Complete()`** 다 —
> T5는 시간 초과가 **실패**다. 그대로 쓰면 아무도 Goal에 안 가고 90초 숨어 있는 것이 정답이 된다.

> **`ReachZoneObjective`도 그대로는 안 된다.** 완료 조건이
> `_reachedPlayers.Count >= GameSession.GetActiveColors().Count` — **존 하나가 전원을 요구**한다.
> 1층 Goal과 2층 Goal로 나누면 양쪽 다 영원히 미완이다.

**그래서 T5 전용 Objective 하나가 두 존을 소유한다:**

| | 내용 |
|---|---|
| 클리어 | **러너가 1층 Goal 존 + 안내자 전원이 2층 Goal 존** 안에 있을 때 `Complete()` |
| 실패 | 90초 경과 → `Fail()` → `StageNetworkState` 직접 실패 통보 |
| **플레이어 사망** | **러너·안내자 구분 없이 누가 죽든 이 클래스가 직접 구독해 `Fail()`** (2026-09-19 확정). T5는 부활 예외 스테이지 |
| 판정 | Host 레인(`ReachZoneObjective`와 동일 이유 — Client가 `Complete()`를 부르면 §11A 위반) |
| UI | **시간만 표시.** 진행률·라운드 표기 없음 |

> **⚠️ 러너 사망 감지 주체가 바뀌었다 (2026-09-19).** 구 설계는 "이 클래스가 잡지 않는다 —
> `StageResetOnPlayerDeath`가 모든 사망을 그 문으로 보낸다"였는데, **그 컴포넌트가 폐기된다**
> (`ReviveSystemDesign.md` §6). 사망이 더 이상 리로드를 뜻하지 않으므로
> `T5RunnerObjective`가 러너의 사망을 직접 구독해야 한다.

**왜 러너에게만 부활을 안 주는가 (2026-09-19 확정):**

1. **실패가 곧 러너 교대 기회다.** 실패 → 리로드 → 러너 재추첨(§1.9). 부활을 넣으면 **같은 사람이
   계속 러너**가 된다. §1.1에서 "러너 교대 없음"으로 접었던 것이 실패 경로로 자연 복원된다.
2. **형태가 맞는다.** `SequenceRingObjective`·`ColorTileChallenge`가 전부 "실수 1회 = 판 다시"다.
   T5 재설계의 이유 자체가 "기능이 모자라서가 아니라 다른 스테이지와 형태가 달라서"(§1.1)였다.
3. **부활 지점 override 훅이 불필요해진다.** 2층 안내자 옆에 부활하면 러너가 2층에 갇히고
   §1.3 때문에 내려올 수 없어 90초 타임아웃까지 교착이다. 부활을 안 주면 이 예외 자체가 없다.

> **참고 — 부활을 허용해도 난이도는 안 무너진다.** 체이서가 소모품이라 러너는 **구조적으로 최대 1번**만
> 죽는다: HP 5 · 데미지 2 → 3방 사망 = 체이서 3마리 소진 → 남은 1마리(1방)로는 부활 HP 3(2방 필요)을
> 못 뚫는다. 그럼에도 위 3가지 이유로 부활을 넣지 않는다.

### 1.8B 2층 압박 — 기존 함정으로 (2026-09-19)

**문제:** 안내자는 위험이 0이다. 러너가 죽으면 아무 잘못 없는 셋이 같이 실패한다.
비대칭을 협동으로 묶어주는 장치가 §1.4 패드 배타 규칙(잘못 밟으면 러너 앞 문이 닫힘) 하나뿐이다.

**폐기한 안 — 2층 체이서 1마리:** ① §2가 "2층에 렌더 메시를 붙이지 말 것"으로
NavMesh 미베이크를 구조적 보장으로 삼고 있는데 그걸 깨야 한다 ② `Stage5ChaserAI`는
러너 clientId만 타겟하므로(`:188-197`) 타겟 분기가 필요하다 ③ 2인이면 안내자 1명이
도망치면서 패드 6개를 다 밟아야 해 인원별 격차가 커진다.

**채택 — 기존 `SpikeTrap`/`ContactDamage`를 2층에 배치**(사용자 작업). 이미 있는 비용만 쓴다.
2층 Goal 존은 안전구역으로 둔다.

> ⚠️ **이게 안내자 사망을 가능하게 만든다 → 그래서 T5는 "누가 죽든 즉시 실패"다**(§1.6, 2026-09-19 확정).
> 안내자에게 부활을 주면 마지막 안내자가 죽었을 때 러너 옆(1층)에 부활해 §1.3 때문에 2층 Goal에
> 못 간다. SSOT는 `ReviveSystemDesign.md` §7.1.

### 1.9 러너 로테이션 (2026-09-19 신규)

**순수 랜덤 재추첨이면 같은 사람이 연속으로 뽑힌다**(4인이면 1/4). "실패가 곧 교대 기회"라는 명분이
성립하려면 **이미 뛴 사람을 제외**해야 한다.

| 항목 | 규칙 |
|---|---|
| 후보 | 전체 플레이어 − **이번 사이클에서 이미 러너를 한 사람** |
| 사이클 종료 | 후보가 비면(전원이 1번씩 함) 기록을 **리셋**하고 다시 전원이 후보 |
| 예 (4인) | 1판 A → 2판 B/C/D 중 → … → 4판에 전원 1회 완료 → 5판부터 다시 전원 후보 |
| 저장 위치 | **`GameSession`** — 씬 리로드를 넘어 살아남아야 한다. `StageNetworkState`는 씬과 함께 사라진다 |
| 범위 | 한 세션(런) 안에서만 의미 있다. T5는 정상 진행이면 1회지만 실패하면 반복된다 |
| 솔로 | 후보가 본인 1명이라 매번 본인. 리셋이 매판 돌 뿐 동작은 같다 |

> 사이클을 "리셋"할지 "1회 완료 → 2회 완료로 승격"할지는 **동작이 같다** — 후보 집합이 전체로
> 되돌아간다는 점에서 동일하므로, 구현은 더 단순한 **리셋**으로 한다.

2층 Goal은 1층 Goal과 **같은 XZ, 2층 높이**에 둔다.

## 2. 씬 구성 — 씬 루트에 둘 것 vs 맵마다 둘 것

맵 7장이 **원점에 겹치므로, 7장에서 똑같은 것은 씬 루트에 하나만 둔다.**
맵 하나당 만들 것이 넷으로 줄고, 시작 홀 구조를 고칠 때 7번 고칠 일이 없어진다.

| 씬 루트에 **하나만** | 맵마다 **7벌** |
|---|---|
| 시작 홀 · `StageStartGate` + `ColoredStartZone` 4 · barrier · 발판 4 · 투명 통로 | **`Walls`** |
| `Floor2F` · `Rails2F` · 2층 발사 구멍 트리거 | **`Doors`** (6색, `NavMeshObstacle` carve) |
| 1층 Goal 존 · 2층 Goal 존 | **`Pads2F`** (6개 — 맵마다 위치가 다르다) |
| 체이서 스폰 4점 · 러너 시작 존 이탈 트리거 | **`Floor1F`** ⚠️ · **`NavMeshSurface`** |

> **⚠️ `Floor1F`는 반드시 맵 자식이어야 한다.** `NavMeshSurface`가 **Children** 수집이라
> 씬 루트로 빼면 1층 바닥이 구워지지 않고 **체이서가 한 발짝도 못 움직인다.**

> **⚠️ 2층은 NavMesh에 구워지지 않는다 — 그리고 그래야 한다.**
> `Floor2F`는 `BoxCollider`만 있고 `MeshRenderer`가 없는데 Surface가 **Render Meshes** 기준이라
> 자동으로 빠진다. 체이서가 2층에 올라갈 방법이 구조적으로 없다. **2층에 렌더 메시를 붙이지 말 것.**

### 3.2 재제작 요구사항 (사용자 작업 — 대기 중)

1. 맵 7장을 **전부 원점에 겹치고**, start = **좌측 하단** / goal = **우측 상단**으로 통일
2. **전부 비활성으로 저장** (작업할 때만 하나 켜기)
3. **맵별 `NavMeshSurface` 7개**로 분리
4. §2 표대로 **공용 오브젝트를 씬 루트로 분리**, 맵에는 `Walls`/`Doors`/`Pads2F`/`Floor1F`/Surface만
5. **시작 홀**: 스폰 4자리 `(0,0,5)/(5,0,0)/(0,0,-5)/(-5,0,0)`를 포함하고, 각 자리는
   **barrier로 칸칸이 분리**(가운데 + 외곽 4방). 자리마다 `ColoredStartZone` + 발판 1개
6. **투명 통로**: 발사 경로를 감싸는 콜라이더(중간 이탈 방지)
7. **2층 발사 구멍** 1개(12×12 정도) + 그 자리에 하향 방지 트리거(§1.3 가)
8. **2층 Goal**: 1층 Goal과 같은 XZ, 2층 높이
9. **체이서 스폰 4점**을 동서남북 **칸 중앙**에
10. 러너 **시작 존 이탈 트리거**(시작 홀을 덮는 존)

> **⚠️ NavMesh 재베이크 시 `Doors`·`Pads2F`를 일시 비활성화해야 한다.**
> `NavMeshModifier(ignoreFromBuild)`가 베이크에서 무시되지 않는 문제가 실제로 있었다.

### 4.3 네트워크 권한

**러너 clientId만 NV 1개.** 맵 인덱스는 **NV에 싣지 않는다** — 시드에서 나오므로
`StageVariantPicker`가 전 머신에서 같은 답을 낸다(`StageVariantPickerBase` 주석의 규약).

러너를 NV로 두는 이유는 **체이서가 Host 전권**이고 매 retarget마다 "타겟의 진실"을 한 곳에서
읽어야 하기 때문이다. 맵과 러너의 권한 모델이 다른 것이 아니라, **읽는 주체가 달라서** 갈린다.

| 것 | 어디서 | 왜 |
|---|---|---|
| 맵 인덱스 | 시드 (NV 없음) | 전 머신 동일 계산. T4 판 선택과 같은 규약 |
| 러너 clientId | **NV 1개** | Host 전권인 체이서가 읽는다 |
| 발판 끄기·barrier 해제 | 각 머신 로컬 (NV/러너에서 파생) | 시각 연출 + 콜라이더 토글이라 로컬로 충분 |
| 체이서 스폰 | Host | 기존 그대로 |
| 문 개폐 | Host (`ColorGatePad` → `ColorGateController`) | 기존 그대로 |

## 6. V단계 (사용자 — 빌드 2개 환경)

**시작 시퀀스 (가장 새롭고 가장 위험)**
- 커튼이 걷힐 때 맵이 **이미 켜져 있는가** (게이트 `t5.map`)
- 3초 뒤 안내자만 발사되고 **러너는 그 자리에 남는가**
- 발사가 2층에 **닿는가** — 모자라면 재발사로 복구되는가 / 넘쳐 난간을 넘지 않는가
- 2층 트리거 발동 시점에 **발판이 꺼지고 barrier가 풀리는가**
- **§1.3 가 안 검증** — 구멍으로 내려가려 하면 다시 올라가는가. 올라가는 중인 사람이
  트리거에 **이중 가속되지 않는가**
- 러너가 시작 존을 벗어날 때 **체이서 4마리**가 나오는가 (솔로 포함)

**진행**
- 체이서가 닫힌 문에 막히고 **열린 문은 통과**하는가
  ← **미확인 항목.** 안 되면 `DoorController.OnOpened`에서 `NavMeshObstacle.carving`을 끌 것
- 체이서가 2층에 못 올라오는가 (Floor2F 미베이크)
- 데미지 2 · 3방 사망이 실제로 어떤 체감인가 / 4마리 소진 후 무위험 구간이 길지 않은가
- 2인: 패드 1개가 고유색 문 8개를 함께 엶 — **정상**

**클리어·실패**
- 러너 1층 Goal + 안내자 전원 2층 Goal → 클리어
- 90초 → 실패 → 리로드 시 **맵·러너 재추첨**
- 러너 사망 → **즉시 실패** → 리로드 (`T5RunnerObjective`가 직접 감지, §1.6)
- **러너 로테이션**(§1.9) — 연속 2판에서 같은 사람이 러너가 되지 않는가 / 4판에 전원 1회씩 도는가
- 안내자는 부활 대상이다 — 2층에서 죽을 방법이 실제로 있는지(난간 넘어 1층 낙하 등) 확인

## 8. 발 헛디디기 쉬운 곳

- **`TipUI`는 String Table을 먼저 읽는다.** 코드 폴백만 고치면 화면은 하나도 안 바뀐다.
  실제로 이 함정에 빠져 "갱신했다"고 잘못 보고한 적이 있다.
- **`ColorGateController.SnapAllClosed()` → `ApplySlotMapping()` 순서.** 스냅이 "적용 완료" 표식을
  세우므로 재매핑이 뒤에 와야 한다.
- **"패드 위에 서 있는데 내 문이 안 열린다" = 사양이다**(§1.4). `OnTriggerStay` 재발동을 넣지 말 것 —
  두 안내자가 각자 패드에 서 있으면 프레임마다 색이 뒤집혀 문이 떨리고 NV가 초당 수십 회 나간다.
- **`ContactKnockback`은 대상도 속도 방향도 보지 않는다.** 러너 제외는 발판을 끄는 것으로,
  이중 가속 방지는 트리거를 나중에 켜는 것으로 푼다(§1.2).
- **`ReachZoneObjective`는 존 하나가 전원을 요구한다**(§1.6). 그대로 두 개 쓰면 둘 다 미완이다.
- **`SurviveTimeObjective`는 시간을 채우면 클리어다**(§1.6). T5와 승패가 반대다.
- **`Floor1F`를 씬 루트로 빼면 체이서가 안 움직인다**(§2).
- **NavMesh 재베이크 시 `Doors`·`Pads2F` 일시 비활성화**(§3.2).
