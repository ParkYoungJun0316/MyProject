### H.4 코드

`CheerService` = Heal·120초 폐기, `ITeamCheerRevert` 있음. **조임 원상 복구(`EsophagusSqueeze`)·안개 걷힘(`EsophagusFog`) 코드 됨(2026-09-06).** `AdvancingWall`은 스케줄 후퇴만. 새 RPC 없음.

**조임/안개 코드 (2026-09-06, 에디터 배선 남음):**
- `EsophagusSqueeze`(`Assets/Scripts/Cheer/EsophagusSqueeze.cs`) — **정수 스텝 확정(2026-09-06).** `target`은 속이 빈 튜브라 non-convex `MeshCollider` 전제 — Unity/PhysX가 스케일 변경마다 BVH를 재굽기(re-cook) 때문에 매 프레임 연속 축소 대신 `secondsPerStep`초마다 `scalePerStep`만큼(기본 2초·1) 정수 계단으로 축소, `minScale`에서 캡. 스텝 사이 프레임은 `target.localScale`을 절대 대입하지 않음(재굽기 호출 자체를 억제). `ITeamCheerRevert` 구현. T1·T3 공용(같은 컴포넌트 재사용).
- `EsophagusFog`(`Assets/Scripts/Cheer/EsophagusFog.cs`) — **연속형 유지.** `RenderSettings.fogDensity`는 콜라이더 재굽기 같은 비용이 없는 순수 셰이더 값이라 정수 스텝으로 바꿀 성능상 이유가 없음 — `densityPerSecond`로 매 프레임 지속 증가, `maxDensity`에서 캡. `ITeamCheerRevert` 구현. T2·T4 공용.
- 둘 다 `BuildRevertOrder`가 지연 없이 현재 ServerTime을 `resumeAtServerTime`으로 즉시 반환 → `Revert()`가 그 시각으로 앵커를 리셋해 원래 상태로 즉시 복귀 후 축소/증가 재개.
- `CheerService`의 창(Warning) 소비 락(`_teamWindowConsumed`)을 다음 외침에도 통과시키려고 `Revert()` 안에서 `NotifyHazardWindow(false)`→`(true)` 펄스를 호출(새 RPC 추가 없이 기존 API 재사용).
- 둘 다 씬당 **하나만** 둘 것(`CheerService.RegisterRevert`가 중복 등록을 경고). `startOnEnable=false`로 두면 `Begin()`을 대화·카운트다운 UnityEvent에 걸어 시작 시점을 미룰 수 있음. `_syncGeneration`은 M 계열과 같이 껐다 켜도 리셋하지 않음(한 머신만 0으로 돌아가면 그 머신이 Host 명령을 낡은 것으로 버려 혼자 안 돌아옴).
- **에디터(사용자, 남음):** T1/T3 씬에 `EsophagusSqueeze` 배치(`target`=식도 원통 BG — `MeshCollider` non-convex 확인, `secondsPerStep`/`scalePerStep`/`minScale` 튜닝 — `minScale`은 시작 스케일보다 작아야 함, 아니면 경고 로그). T2/T4 씬에 `EsophagusFog` 배치(`densityPerSecond`/`maxDensity`/`fogColor` 튜닝). 안개는 URP **빌트인 Fog**(Lighting > Environment)를 코드가 켜므로 별도 Volume 오버라이드 없음 — URP Lit 계열만 반영되고 커스텀/Unlit 셰이더(Boulder 등)는 범위 밖. `TeamCheerWarningUI`는 M과 동일하게 `CheerService.OnHazardWindowChanged` 구독 — 씬에 해당 UI prefab 배치 여부만 확인.

**지속형 모델 확정 (2026-09-06, 위 코드로 구현됨):**
- 창(Warning~Attack 닫힘) 개념 없음 — `IsAvailable`이 사실상 항상 true, 응원은 언제든 유효. M4.2 AttackSweep(윈도우형, 놓치면 다음 창까지 방치)와는 다른 모델 — Tongue는 그대로 두고 T만 이 모델로 감.
- **조임** = 식도 원통(BG) `transform.localScale` x/y를 지속적으로 축소(전방향, 축 구분 없음) → 최소 반경에서 캡. 최소 반경은 **인스펙터 노출**(테스트하며 튜닝). 응원 성공 시 원래 스케일로 복귀. `ColorWall`은 원통과 별개로 좌우에 박힌 패널(순전진 0 `AdvancingWall`, 색 일치=잠깐 멈춤)로 남고 되돌림 대상 아님(볼더·Spike와 같은 압력).
- **안개** = Render Fog(`RenderSettings.fog`) 밀도를 지속적으로 증가(거리 기반) → 최대 밀도 캡(**인스펙터 노출**). 응원 성공 시 밀도 0으로 복귀 후 다시 증가 재개. 씬 전역 적용(구간 분리 없음) — 팀원 시야도 동일하게 영향받음(Host/Client 차이 없음). Boulder 등 커스텀 셰이더 요소는 이 작업 범위 밖.
- 둘 다 새 RPC/NetworkVariable 없음 — `WallWaveController`/`AdvancingWall`과 같은 "각 머신 `ServerTime` 폴링 + 로컬 결정론적 계산" 패턴. T.Stage는 대부분 페이즈 1개라 Tongue의 `PhaseStartServerTime` 앵커·`ResolveFirstWindow` 같은 첫 창 동기화가 불필요 — 타이밍은 `CheerService`의 `BuildRevertOrder`/`Revert(generation, resumeAtServerTime)` 핸드셰이크로 이미 맞춰짐.

## 2. 팀 응원 (식도) **[확정]**

| 판 | 효과 |
|----|------|
| T1·T3 | 조임 **원상 복구** |

## 3. 조임 **[확정: 개념 + 지속형 모델 2026-09-06]**

**원상 복구는 T1·T3만.** T.Boss는 페이즈 때.

**메카닉 교체:** 좌우/위아래 축 구분(AdvancingWall 평면 벽 두 짝)을 폐기하고, **식도 원통(BG) 자체의 반경을 축소**하는 것으로 통일. 원통은 속이 빈 튜브라 콜라이더는 non-convex `MeshCollider` 전제 — Unity/PhysX가 스케일이 바뀔 때마다 내부 BVH를 재굽기(re-cook)하므로 매 프레임 연속 축소 대신 **정수 스텝**(2026-09-06 확정)으로 간다: 예시 스케일 10,10(×,y) → 9,9 → 8,8 → … **N초마다 한 단계씩**(기본 2초·1칸, 인스펙터 노출) 줄어들고, **최소 반경에서 캡**(즉사 방지, 핸디캡만 — 다른 M 계열 함정과 동일 원칙: 조임 자체는 데미지 없음). 최소 반경 값도 **인스펙터에 노출**해 테스트하며 튜닝. 안개(§5)는 콜라이더 비용이 없어 이 제약이 없음 — 연속형 그대로.

- **창 없음.** Warning~Attack으로 응원 유효 구간을 가르지 않음 — 반경이 얼마나 줄어 있든 **응원은 항상 유효**하고, 성공하면 그 즉시 원래 스케일로 복귀. 복구 후 다시 축소가 재개된다.
- 전방향으로 균등하게 줄기 때문에 **T1·T3·T.Boss 모두 같은 메카닉**(축을 좌우/위아래 중 고를 필요 없음). T1↔T3의 차이는 이제 조임 자체가 아니라 **ColorWall 색 복잡도**(고유 → 흑백)에서만 남는다.
- **ColorWall = 별도 좌우 압박.** 원통 반경과는 독립된 옆벽 패널(순전진 0 `AdvancingWall` — 매 사이클 전진 후 제자리 복귀, 누적 없음)에 붙여서 색 일치=잠깐 멈춤만 준다. 되돌림(`ITeamCheerRevert`) 대상이 아님 — 볼더·Spike·Thron·점액·넉백과 같은 "압력" 취급.

패드(Door_3)와 조임은 다른 장면. T3 2인 장면은 **외침 원상 복구**만. ColorWall 멈춤은 색 일. 볼더·Spike·Thron·점액·넉백은 압력.

안 함: T4·T5·T.Boss에 지금 원상 복구, 계속 고함으로 조임을 붙잡아 두기(누적만 리셋됨, 영구 정지 아님), T1에 고유+흑백 한 번에, ColorWall을 동시 고유 두 벽 필수 멈춤으로 2인 게이트 만들기.

코드: `EsophagusSqueeze`, §H.4. 새 RPC 없음 — `ServerTime` 폴링 결정론적 계산(정수 스텝 번호).

## 5. 안개 **[확정: 개념 + 지속형/Render Fog 모델 2026-09-06]**

식도의 두 번째 일 = 시야를 가림. M 닫힘 암흑(거리 무관 화면 전체 알파)과는 다른 메커니즘 — **거리 기반 Render Fog**(`RenderSettings.fog`). 가까운 건 보이고 먼 것만 흐려짐. 파티클 바닥 안개는 밀도를 올리면 렉이 걸려서 **폐기** — Render Fog는 셰이더에 이미 있는 계산이라 훨씬 저렴함.

초출 **T2**. 복습 **T4**. T5·T.Boss는 지금 안 붙임.

- **씬 전역 적용, 구간 분리 없음.** `RenderSettings.fog`는 씬 단위 설정이라 같은 씬 안에서 안개 구간/비안개 구간을 나누지 않음(T.Stage는 대부분 페이즈 1개라 문제 없음).
- **창 없음, 지속형.** 밀도가 시간에 비례해 계속 증가 → **최대 밀도에서 캡**(인스펙터 노출, 시야 완전 차단은 아님). 응원은 언제든 유효, 성공하면 밀도가 그 즉시 0으로 복귀하고 다시 증가가 재개된다.
- **팀원 시야도 동일하게 영향받음** — 거리 기반이라 멀리 있는 팀원도 잘 안 보이게 됨. Host/Client 차이 없이 씬에 적용되는 전역 설정.
- Boulder 등 **커스텀 셰이더를 쓰는 요소는 이 작업 범위 밖** — 필요하면 그쪽에서 별도로 Fog 반영.

T2 = 타일이 곧 판. 거리 기반이라 "가까이 가야 읽힌다"는 느낌이 자연스럽게 나옴 — 원래 취지("이속만으로는 타일·복도를 못 읽는다")에 오히려 더 맞음. T4 = **구멍 난 바닥**과 **올라온 Door 길**을 보고 달려야 함 (넉백에 튕겨 구멍으로 낙사). T5는 캐릭터 추적이라 기본 안 씀.

Memory 미리보기 정답을 다시 켜지 않음(안개가 걷혀도 정답 하이라이트 아님, 그 순간 챌린지 상태의 바닥만).

2인: 한 명이 외치지 않으면 안개가 걷히지 않는다.

안 함: 미리보기 Safe/Trap·색 경로를 다시 보여주기, 계속 고함으로 안개를 붙잡아 두기(누적만 리셋됨), T5·T.Boss에 지금 붙이기.

코드: `EsophagusFog`, §H.4. 연속형 유지(콜라이더 재굽기 비용이 없어 조임과 달리 정수 스텝 불필요). 새 RPC 없음 — `ServerTime` 폴링 결정론적 계산, 씬 로드 시각 앵커 불필요.
