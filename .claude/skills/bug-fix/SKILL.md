# bug-fix — 버그 처리 절차

핵심 규칙: **추론은 해도 되지만, 추론을 원인으로 확정해 코드를 고치는 건 금지.** 확정은 코드 추적이나 로그로만 한다. 모르면 모른다고 한다.

## 순서

1. **증상 전부 받아 적기** — 사용자가 말한 증상을 빠짐없이 목록으로. 재현 조건(언제·어느 씬·Host/클라 중 누구·몇 명·몇 번째).
2. **경로 추적** — 증상이 나는 자리의 호출 경로(누가 → 누굴 → 순서)를 따라 관련 스크립트를 전부 읽는다. 읽은 파일 목록을 남긴다. 씬을 넘어 살아남는 static 플래그·DontDestroyOnLoad 를 먼저 의심한다.
3. **대조** — 세운 가설이 **모든** 증상을 설명하는지 확인한다. 증상별로 "어떤 가드를 거치나"를 표로 대조. 하나라도 설명 못 하면 확정 아님. 문서의 기존 미해결 버그 목록에 끼워맞추지 않는다.
4. **갈림길**
   - **코드로 확정됨** (원인 줄 번호를 짚을 수 있고 모든 증상이 맞음) → 5번으로.
   - **확정 안 됨** → `Debug.Log("[DBG] ...")` 를 의심 지점에 넣는 수정만 제안한다. 사용자가 재현하면 MCP 로 콘솔을 읽어 확정한다. 확정되면 5번.
5. **보고하고 멈춘다** — 아래 형식. 승인 전에는 고치지 않는다.
6. **승인 뒤 수정** — 원인 한 곳만 고친다. 증상 난 곳에 복구 분기·재호출을 덧대지 않는다. 넣었던 `[DBG]` 로그는 같은 수정에서 지운다.
7. **확인 방법 제시** — 사용자가 뭘 눌러서 뭘 보면 되는지(멀티면 ParrelSync/빌드 두 개로 몇 명). 끝나면 커밋 권유.

## 보고 형식

```
증상: 1. ... 2. ...
읽은 파일: ...
원인: (확정 | 미확정) — 파일:줄, 한 줄 설명
모든 증상 설명되나: 예 / 아니오(어느 증상이 안 맞나)
제안: (수정 내용 | 넣을 [DBG] 로그 위치)
확인 방법: ...
```

- 사용자의 "좋아 / 그래 / 알겠어"를 승인으로 읽기
